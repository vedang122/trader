hands yfinance a `curl_cffi` chrome-impersonation session, and this
environment's MITM proxy resets that TLS fingerprint (curl error 35); yfinance
then retries under a default UA that Yahoo blocks. Confirmed by controlled test
here: curl_cffi → 0 rows, plain `requests.Session` with a browser UA → full
clean bars including today's. One line in `_http_session()`.

It was **not applied**. This run may commit only `state/`. Patching the
enforcement layer un-reviewed, to unlock trades otherwise unavailable, is the
exact failure the two-brain rule exists to prevent — every fill would be
journaled as if the committed engine produced it. The risk-officer steelmanned
the opposite case (a stop is a safety control; emergency repair is normally
permitted) and still accepted the refusal: the event is ~23h out, so loud
escalation substitutes fully for self-patching.
